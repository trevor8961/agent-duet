# agent-duet

> 你和 agent 的二重唱 —— 把瀑布流变成分声部的乐谱。

Agent 的输出天然是"二分"的：一个声部对你正式歌唱（回复、结果），
另一个声部在低声吟唱（思考、嘀咕、蛐蛐）。agent-duet 把这两个声部
分开呈现，并管好每一场演出的档案。

名字来源：二分心智（Bicameral Mind）——远古心智一室发声、一室执行。
今天的 agent 正处于这个阶段。

## 要解决的问题

### 1. Session 档案缺失（地基）

长时间 session 容易忘记是在哪个目录开的；重启后即使翻 session 历史
也很难找回。session 的「时间 + 工作目录 + 话题」没有被结构化记录。

→ **每个 session 一份档案（dossier）：什么时候开的、在哪个目录、
聊了什么话题、处于什么状态，随时可检索。**

### 2. 输出消费方式糟糕

一次提示词触发的输出里，正式回复和 agent 的"喃喃自语"以瀑布流
形式混在一起涌向用户，信息密度低、难以回顾。

→ **分声部呈现：主旋律（正式回复）与低声部（思考过程）分离，
各自以适合的方式组织。**

### 3. 模式无差别呈现

auto / manual / plan 等模式下 agent 行为截然不同（是否先询问、
是否按规划步骤推进），但终端里呈现方式完全相同，不合理。

→ **模式感知 UI：不同模式下，用户看到的信息组织方式应该不同。**
（具体形态待设计）

### 4. 多 Agent 切换

不同 agent（pi、claude code…）体验割裂，缺少统一入口。

→ **一个页面选择当前使用的 agent，统一操作体验。**

## Non-goals（暂不做）

- 不造新 agent，只做现有 agent 的体验层
- 不做远程/云端服务，先立足本地
- 不支持导入既有 session 历史（从用本工具起，数据才结构化）

## Vision（远期）

结构化会话数据的终极消费者不止是用户，还有 agent 自己：
通过离线「冥想」任务复盘自己的思考链与踩坑记录，agent 自己蒸馏并维护
工作规范，摆脱每次 session 失忆重采坑的循环——从被用户约束，
走向自我约束。

## Architecture（已定）

```
浏览器页面 ←→ 本地后端 ←→ claude code (headless: claude -p --output-format stream-json)
                    ↕
              SQLite（data/ 目录）
```

- 后端以事件流方式调用 agent，thinking / text / tool_use 按 type 分开落库
- v1 用户在本工具页面内对话，保证全量数据结构化
- 本地直跑，状态全部收敛到 `data/` 单目录
