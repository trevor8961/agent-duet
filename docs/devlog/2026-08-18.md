# 开发日志 · 2026-08-18

> agent-duet 第一天：从起名到第一版可用 UI。

## 今日主题

项目从零起步：命名 → 需求对齐 → 架构设计 → 数据模型 → 事件流解析 → 编排落库 → 读接口 → 前端三栏 UI，并建立"真实数据驱动 + 无头浏览器验收"的工作方法。

## 项目缘起与命名

- 痛点（四个）：① session 档案缺失（长会话忘了在哪开的、重启难找回）；② 终端瀑布流消费差（正式回复与思考嘀咕混在一起）；③ 模式（auto/manual/plan）无差别呈现；④ 多 agent 切换割裂
- 命名讨论从 `bicameral`（二分心智，西部世界梗）→ 接地气化 → 定名 **agent-duet**（二重唱：主旋律=正式回复，低声部=思考嘀咕）
- 后续引申出 **North Star（痛点5）**：结构化数据不仅给人看，也让 agent 自己消费——离线"冥想"复盘踩坑、自己生成工作规范，从被约束走向自我约束（"养马"隐喻）

## 关键决策

- **技术栈**：后端 Python + FastAPI；前端 Vite + Vue；DB 用 SQLite（WAL，单文件不黑箱）；读侧组装用 pydantic-resolve（仅 Core API，不用 ERD/MCP）
- **通用协议层**：messages 用规范 schema（role + channel 枚举 + content JSON），任何 agent 输出都翻译进来，与 profile 解耦
- **profile 表**：每个"agent × 供应商模型"一条记录（mode_map / capabilities），前端按能力声明渲染而非按 agent 身份
- **意图五分类**（询问/探索/验证/计划/实施）挂 turn 而非 message，v1 手选
- **原始优先原则**：原始事件流存文件（raw_path），派生数据永不落库、读时算——保证未来可重放补齐
- **不支持导入历史 session**：各家内部格式无底洞，边界定为"从用本工具起数据才结构化"

## 数据模型（四表）

```
agents(profile) ──< sessions ──< turns ──< messages
                                    └──< permission_requests（次日新增）
```

- sessions：title/cwd/agent_id/mode/status
- turns：seq/intent/status/effective_mode/model/cost/raw_path/granted_from（次日）
- messages：role/channel(text|thinking|tool_use|tool_result)/content JSON/tool_use_id

## 实测发现（docs/samples/）

- `claude -p --output-format stream-json --verbose` 必带 verbose；stderr 有噪声行
- 事件类型：system(init/thinking_tokens)/assistant/user/result
- **第三方 DeepSeek 接口正确传递 thinking 块**（分声部地基成立）
- 权限拒绝时 `result.is_error` 仍为 false，错误信号在 permission_denials——后来驱动了 denied/error 状态分离
- 空 thinking 块 `{"text":""}` 是真实形态（两次现身才正式处理）
- 多工具可并行发出（同一条 assistant 消息两个 tool_use）

## 工程踩坑档案

1. `claude -p` 权限拒绝 = is_error false → 判定不能只看 result
2. ASGITransport 缓冲 SSE 流式响应 → "实时性"断言必须看服务端 ts，真·实时靠真机
3. 纵向 flex 滚动容器子项默认 `flex-shrink:1`，内容超高时 widget 被压扁（"时隐时现"根因）
4. `<details>` 设 display 会破坏关闭态原生隐藏
5. macOS 悬叠式滚动条不可见 → 用 mask 渐隐提示，不赌滚动条策略
6. SQLAlchemy `default=` 存的是字面量字符串，`server_default=text("datetime('now')")` 才对
7. Vue 模板作用域没有 `location` 等浏览器全局 → 逻辑进 script 函数

## 测试方法论（与用户共同确立）

- 测试拟自**使用场景**，不是凑覆盖率；mock 只隔离进程/LLM 边界，SQLite 用真库
- 用 docs/samples 真实事件流做 fixture，TDD 先写规格
- 引入 Playwright 无头浏览器做前端布局/行为探针（`frontend/probes/`）
- **用户验收门禁**：UI 改动须用户验收合格才 commit+push

## 关键讨论记录

- **"agent 蒸馏自己"**：不是 ML 蒸馏（不改权重），是行为经验蒸馏成外部文字规范；每个 session 失忆地生、经验沉淀在库里被后来个体继承——"物种级经验池"
- **Hermes Agent 对比**：同构但不同层——Hermes 是完整 agent（经验锁在自身），agent-duet 是 agent 无关的数据层
- **三声部语义**：主旋律（回复）/低声部（思考）/动作（工具），工具不属于低声部
- **事务状态 vs 交互结论**（次日深化）：完成/未完成/失败是事务状态，批准/拒绝/超时是每次授权的交互结论，两者正交
