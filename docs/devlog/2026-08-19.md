# 开发日志 · 2026-08-19

> 第二天：SSE 假死修复 + 事中授权（interactive permission approval）全链路。

## 今日主题

修复一个 SSE 假死 bug，然后从零实现**事中授权**——agent 运行中遇到权限请求时，页面弹出授权卡、用户批准/拒绝/超时，授权状态作为一等记录落库并挂回工具卡。同时把事务状态重构为四档语义。

## 一、SSE 假死修复

**现象**：用户发请求后状态条"0s"静止、token 停在幽灵值、页面假死；但后端其实正常跑完。

**根因**：SSE 首次订阅时后端总线**从 cursor=0 回放全部历史事件**，回放流里带着上一轮的旧 `turn_done`，前端误收后立即停表断流；`load()` 又把 running 拉起来，但流已断、成孤儿。

**修复**：首次订阅只看实时流；历史回放只在客户端带 `Last-Event-ID`（真·断线重连）时发生。姊妹修复：中途打开运行中的会话补上 `startWorking()`（计时器启动）。

## 二、事中授权（plan_permission_approval.md）

**动机**：之前 headless 下权限请求被自动拒绝，用户只能事后看 denied 再"授权并继续"，多一轮交互且无法事中把关。

**技术路径 A**：调用层从 `claude -p` 子进程换成 **claude-agent-sdk**，其 `can_use_tool` 异步回调原生支持阻塞等待用户决策。

**核心攻坚（最大坑）**：
1. `output_format="stream-json"` 会**关闭 SDK 双向控制协议**，can_use_tool 回调不被服务、CLI 退回 auto-deny 且零报错。去掉 output_format、用 SDK 原生流式消息后回调立即生效
2. 回调返回值必须是 `PermissionResultAllow/Deny` **类型实例**，裸 dict 会被 CLI 拒绝（报 "got <class 'dict'>"）
3. **权限记忆**：同一 session 授权过 Write 后，claude 不再询问——测试必须用全新会话

**落库设计（DB-first）**：`permission_requests` 表（request_id/tool_name/tool_input/tool_use_id/status/timeout_at），pending 落库、重启可对账；运行时 asyncio.Event 等待，超时默认拒绝。

**验证**：47 单测通过 + 真实 claude/DeepSeek 端到端（弹卡 → 批准 → agent 继续 → 徽章落工具卡）。

## 三、事务状态四档重构（与用户的语义讨论）

**核心洞察（用户提出）**：不要枚举权限组合（会掉进"全批准/批准+拒绝+超时/全超时/全拒绝"的黑洞）。两层正交：

| 层 | 表达 | 取值 |
|---|---|---|
| 事务状态（turn） | 事情做成没有 | 完成 / 未完成 / 失败 / 已终止 |
| 交互结论（permission） | 每次授权用户怎么答 | approved / denied / timeout |

- `denied`（权限挡住）→ **未完成**；`error`（真出错）→ **失败**；用户主动停止 → **已终止**（"取消"改为"终止"，语义更准）
- "授权并继续"降级为**动作按钮**（仅当本轮有 denied/timeout 交互时出现），不再伪装成状态
- **授权状态挂回工具卡**：permission 记录补 `tool_use_id`，授权徽章直接标在对应的 🔧 工具卡上（"每个操作的授权状态"和"哪个操作"天然绑定，多个写操作不乱）

## 四、授权消息的系统身份

授权重跑（`granted_from` 非空）落库 `role=system`，前端用居中灰胶囊样式，不再冒充用户提问（之前"继续执行刚才被拒的文件操作"看起来像用户自己发的）。

## 工程踩坑档案（新增）

1. SDK 双向控制协议依赖原生流式，禁 stream-json
2. SDK 回调返回类型契约（PermissionResult 实例非 dict）
3. can_use_tool 在 uvicorn BackgroundTask 下正常（曾误判为环境问题，实为权限记忆干扰）
4. 清理脚本必须按 session_id 白名单，不按 turn_id 范围猜（曾误删用户一轮 turn）
